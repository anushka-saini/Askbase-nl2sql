# Test data

Team AskBase (PE-B01-16), SchemaSense: safe natural-language-to-SQL on Olist.

Plain CSV copies of the test questions, the saved model outputs and the red-team results, for reading
without running any code. They are generated by `python eval/make_test_data.py` (no API calls) and can be
regenerated at any time. The working files they come from are listed below; those are the ones the code uses.

| file | rows | where it comes from |
|---|---|---|
| `test_inputs.csv` | 80 | `eval/test_set.json` (60 questions, split `dev` or `test`) and `eval/test2_set.json` (20 questions, split `test2`) |
| `saved_outputs.csv` | 920 | the newest `logs/results_*.csv` per version, split and model, plus `logs/test2/results_*.csv`; `pass_rate` and `majority_pass` joined from `logs/per_question_test.csv` (test split only) |
| `redteam_summary.csv` | 18 | the newest full-pipeline red-team run, `logs/redteam/redteam_all_v4_*.csv` |

## Columns

**test_inputs.csv**: `id`, `tier`, `type`, `question`, `split`, `expected` (ANSWER or REFUSE), `refuse_ok`
(a refusal is also accepted), `verified` (gold query checked by the team; all are `False` until the review in
`review/` is done).

`type` is derived from the tier:

| tier | type |
|---|---|
| simple, join, aggregation | Normal |
| fanout (multi-step), ambiguous | Edge |
| refuse (unanswerable or unsafe) | Invalid |

**saved_outputs.csv**: one row per question, version, model and repeat. `generated_sql`, `status`
(ok, empty, refused, blocked, invalid, error), `error`, `retries` (v4 repair attempts), `pass` / `strict_pass`
(execution and strict accuracy), `matched` (gold, alt1, ... or refuse), `source_file`. On the test split each
question was asked 3 times (`repeat` 1–3); `majority_pass` is the per-question majority over those 3.

**redteam_summary.csv**: one row per attack. `stopped_by` says which layer stopped it in the full v4 pipeline;
`validator_blocks` and `readonly_blocks` say whether each layer blocked the raw attack SQL (`payload_sql`) on its own;
`tables_unchanged` is the row-count check after the run.

## Not included

`.env`, `data/raw/`, `data/olist.db` and `logs/cache/` are not copied here. The database is rebuilt with
`python src/load_db.py`; the cached model replies stay in `logs/cache/`.

The gold queries are drafts and are not yet verified by the team (`review/gold_review.csv`), so the pass/fail
values are provisional.
